# Termoil feature matrix

Date: 2026-11-02. Version: 0.2.0 plus the commits on the `task-2458` branch that are on main or about to be.

This file lists every feature row in `docs/research/feature-parity.md` and says what Termoil does for it. The rows come from section 1 (the feature matrix), section 3 (the ten features users cite most often) and section 4 (the specifications Termoil must implement). Section 2 of that file is prose about each emulator and has no rows.

## What the statuses mean

- **done**: the feature is implemented. The Where column names the file or module and the Test column names the test that covers it. A row that is done but has no automated test says so in the Test column, and the Notes column says why.
- **partial**: part of the feature works. The Notes column says what exists and what is missing.
- **deferred**: the feature is not in 1.0. The Notes column gives the reason: a section of `docs/PRD.md` (5.5 "later" or 5.6 "non goals"), or the feature was not built.

Paths are relative to `crates/` unless they start with `corpus`, `docs`, `installer`, `shell-integration` or `tools`. "VT script" means a text script in `corpus/vt/*.test` that `termoil-vt/tests/script.rs` runs.

## Limits that apply to several rows

- The macOS builds are cross compiled on Windows, signed and notarised. They have not run on a Mac. Every macOS statement below is a statement about code that compiles, not about code that has been seen working.
- The Linux packages and the Linux tests have run under WSL only, not in a full Wayland or X11 desktop session.
- iTerm2 inline images accept PNG only.
- The quick terminal on Wayland needs the GlobalShortcuts portal, which several compositors do not offer.
- Translucent windows on Windows wait for the GPU renderer, because the CPU renderer presents through `softbuffer` without an alpha channel.
- Screen reader access covers the visible screen text. Scrollback is not exposed.
